# déjà vu

<p align="center">
  <em>同じバグを再デバッグしない。同じ判断を一つの視点で下さない。<br>
  二つのスキル。依存ゼロ。AI コーディング最大の隠れたコストを排除。</em>
</p>

<br>

## なぜ déjà vu か

AI コーディング最大の隠れたコストは、GPU 時間でも API 料金でもなく、**再思考**です。

**同じエラーを 3 回デバッグ。** そのたびに AI はコードを読み直し、スタックトレースを再解析し、修正を再導出します。再調査に費やされるトークンは、実際の修正コストをはるかに上回ります。

**同じ判断、一つの視点。** AI は実行は得意ですが、「見落としている視点は？」とは言いません。誰も前提を疑わず、本番環境で破綻します。

déjà vu は二つのことを行います：
- **gotcha** — デバッグセッションを記録し、次回即座に呼び出す。再調査なし
- **flip** — 決定を確定する前に、誰も考えなかった視点から検証する

二つのスキルは補完的：gotcha は**繰り返し作業**のトークンを節約し、flip は**誤った決定**からあなたを守ります。

## gotcha — トラブルシューティングメモリ

### 解決する問題

CI 障害をデバッグします。10 ラウンドの会話の後、根本原因を特定：Docker ベースイメージが古い SHA を固定していた。翌週、同じエラー。AI はまたゼロから始めます — さらに 10 ラウンド。**同じ答えに二度支払いました。**

gotcha はこれを一度だけにします。

### 使い方

```bash
# バグ修正後、経験を保存
/gotcha save
# → AI が直近のデバッグセッションをスキャン
# → 症状・根本原因・修正内容を抽出
# → 下書きを表示、確認で保存

# 次回は再調査せずに検索
/gotcha CI killed
# → grep でミリ秒検索
# → 1 件ヒット → 完全な内容を注入、デバッグをスキップ
# → 複数ヒット → タイトル一覧から選択

# gotcha ライブラリの管理
/gotcha                    # 全件表示、新着順
/gotcha fix <slug>         # 修正済みにマーク（記録保持、マッチ時に注釈）
/gotcha delete <slug>      # 削除（確認あり）
```

### ファイル形式

各 gotcha は `.claude/gotchas/` 下のプレーン Markdown ファイルです：

```markdown
---
tags: [CI, OOM, GitHub-Actions]
created: "2026-05-21"
fixed: false
---

# 症状
CI 报 killed 但本地正常

# 原因
GitHub Actions runner 只有 7GB 内存

# 解法
NODE_OPTIONS=--max-old-space-size=4096
```

可読、編集可能、git 追跡可能。ブラックボックスはありません。

### 設計

- **ミス時にトークン消費ゼロ** — インデックス事前注入なし、バックグラウンドマッチなし。`/gotcha` 呼び出し時のみ検索
- **非侵入的** — 保存するかはあなた次第。セッション終了時に一度だけ優しくリマインド
- **設定可能** — ヒントレベル、セッションリマインダー、重複検出の厳密さをパラメータで調整可能

## flip — 視点転換

### 解決する問題

あなたと AI が選択肢を議論し、Redis をキャッシュに採用することに決定します。議論全体を通じて「どうやって Redis キャッシュを実装するか」の枠内にいます。「キャッシュは本当に必要か？」「単一の大きなオブジェクトで Redis が破綻しないか？」とは誰も問いません。**これらの盲点は本番環境で表面化します。**

flip は、出荷前に議論に欠けていた視点から結論を検証します。

### 使い方

```bash
# 最新の結論を見落としている視点から検証
/flip
# → AI が問う：この議論に欠けていた視点は？
# → その欠けた視点から結論を検証
# → 盲点発見 → 修正提案。盲点なし → 結論を確認

# 特定の結論を検証
/flip "use Redis for caching"
```

### どの視点か

flip は議論に欠けている視点を動的に選択します。「反対意見」がデフォルトではありません：

| 視点 | 問い |
|---|---|
| 反対 | 「やらなかったら？」 |
| コスト | 「どれだけの時間/費用？価値は？」 |
| 簡素化 | 「もっと少なくできる？スキップできる？」 |
| 時間 | 「3 ヶ月後に何を後悔するか？」 |
| 新人 | 「文脈を知らない人が混乱することは？」 |
| 極端 | 「予期せぬ使われ方でどこが壊れる？」 |
| 規模 | 「10 倍のボリュームで最初に何が失敗する？」 |

呼び出しごとに 1 つの視点 — 盲点を明らかにする可能性が最も高いものを。

### 設計

- **議論ではない** — 視点がチェックアウトすれば確認して次へ。反対のための反対ではない
- **ブレインストーミングではない** — ブレインストーミングは可能性を探り、flip は既存の結論を検証する
- **あなたが決める** — flip は視点を提供し、結論は常にあなたのもの
- **設定可能** — ヒントレベル：オフ / 重要な決定時 / すべての結論時

## なぜ déjà vu か

| | 既存の方法 | déjà vu |
|---|---|---|
| 経験の保存 | CLAUDE.md / .cursorrules を手動で書く。人は忘れる | 1 コマンド、AI が抽出、あなたが確認 |
| 経験の検索 | grep 手動、チャット履歴スクロール、AI に再質問 | `/gotcha <キーワード>`、ミリ秒でヒット |
| 決定のレビュー | 直感、経験、コードレビュー | `/flip`、体系的な視点転換 |
| トークンオーバーヘッド | ルールファイルを全ロード。使わなくても支払う | 事前注入ゼロ。検索時のみ支払う |
| 依存関係 | 埋め込み API、ベクトルデータベース | grep + ファイルシステム、外部依存ゼロ |

---

## 設計理念

- **トークンを無駄にしない** — オンデマンド検索のみ。事前注入もバックグラウンドマッチもなし
- **外部依存ゼロ** — grep + ファイルシステム。理解可能、デバッグ可能、コストゼロ
- **集中力を妨げない** — 保存するかはあなた次第。一度の優しいリマインド、しつこくしない
- **あなたが主導** — 経験と視点を提供するだけ。結論は常にあなたのもの
