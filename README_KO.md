## 왜 déjà vu 인가

AI 코딩에서 가장 큰 숨은 비용은 GPU 시간이나 API 요금이 아닌 **재사고**입니다.

**같은 오류, 세 번의 디버깅.** 매번 AI가 코드를 다시 읽고, 스택 트레이스를 재분석하고, 수정안을 다시 도출합니다. 재조사에 소모되는 토큰이 실제 수정 비용을 훨씬 능가합니다.

**같은 결정, 하나의 관점.** AI는 실행에는 뛰어나지만 "우리가 놓치고 있는 각도가 뭐지?"라고 말하지 않습니다. 아무도 가정에 의문을 제기하지 않고, 운영 환경에서 깨집니다.

déjà vu는 두 가지 일을 합니다:
- **gotcha** — 디버깅 세션을 기록하고, 다음 번에 즉시 불러옵니다. 재조사 없음
- **flip** — 결정을 확정하기 전에, 아무도 고려하지 않은 관점에서 검토합니다

두 스킬은 상호 보완적: gotcha는 **반복 작업**의 토큰을 절약하고, flip은 **잘못된 결정**으로부터 보호합니다.

## gotcha — 트러블슈팅 메모리

### 해결하는 문제

CI 장애를 디버깅합니다. 10라운드의 대화 끝에 근본 원인을 찾아냅니다: Docker 베이스 이미지가 이전 SHA를 고정하고 있었음. 다음 주, 같은 오류. AI가 처음부터 다시 시작합니다 — 또 10라운드. **같은 답에 두 번 지불했습니다.**

gotcha는 이런 일이 한 번만 일어나도록 합니다.

### 사용법

```bash
# 버그 수정 후, 경험 저장
/gotcha save
# → AI가 최근 디버깅 세션을 스캔
# → 증상, 근본 원인, 해결책 추출
# → 초안 제시, 확인하면 저장

# 다음 번에는 재조사 대신 검색
/gotcha CI killed
# → grep으로 밀리초 검색
# → 1건 히트 → 전체 내용 주입, 디버깅 건너뛰기
# → 여러 건 → 제목 목록에서 선택

# gotcha 라이브러리 관리
/gotcha                    # 전체 목록, 최신순
/gotcha fix <slug>         # 수정 완료 표시 (기록 유지, 매칭 시 주석)
/gotcha delete <slug>      # 삭제 (확인 후)
```

### 파일 형식

각 gotcha는 `.claude/gotchas/` 아래의 평범한 Markdown 파일입니다:

```markdown
---
tags: [CI, OOM, GitHub-Actions]
created: "2026-05-21"
fixed: false
---

# 症状
CI 报 killed 但本地正常

# 原因
GitHub Actions runner 只有 7GB 内存

# 解法
NODE_OPTIONS=--max-old-space-size=4096
```

읽을 수 있고, 편집 가능하며, git 추적 가능합니다. 블랙박스가 없습니다.

### 설계

- **미스 시 토큰 비용 제로** — 사전 인덱스 주입 없음, 백그라운드 매칭 없음. `/gotcha` 호출 시에만 검색
- **비침투적** — 저장 여부는 당신이 결정. 세션 종료 시 한 번만 부드럽게 알림
- **설정 가능** — 힌트 레벨, 세션 리마인더, 중복 감지 엄격도를 매개변수로 조정 가능

## flip — 관점 전환

### 해결하는 문제

당신과 AI가 옵션을 논의하고 Redis를 캐싱에 사용하기로 결정합니다. 논의 내내 "어떻게 Redis 캐시를 구현할까"라는 틀 안에 있습니다. "캐시가 정말 필요한가?" "단일 대형 객체가 Redis를 폭발시키지 않을까?"라고 아무도 묻지 않습니다. **이런 맹점은 운영 환경에서 드러납니다.**

flip은 배포 전에 논의에 빠졌던 관점에서 결론을 검토합니다.

### 사용법

```bash
# 최신 결론을 놓친 관점에서 검토
/flip
# → AI가 묻는다: 이 논의에 빠진 관점은?
# → 그 빠진 관점에서 결론 검토
# → 맹점 발견 → 수정 제안. 맹점 없음 → 결론 확인

# 특정 결론 검토
/flip "use Redis for caching"
```

### 어떤 관점인가

flip은 논의에 빠진 관점을 동적으로 선택합니다. "반대"가 기본값이 아닙니다:

| 관점 | 질문 |
|---|---|
| 반대 | "하지 않으면 어떻게 될까?" |
| 비용 | "시간/비용이 얼마나? 가치가 있는가?" |
| 단순화 | "더 적게 할 수 있을까? 건너뛸 수 있을까?" |
| 시간 | "3개월 후에 무엇을 후회할까?" |
| 신입 | "맥락을 모르는 사람이 혼란스러워할 점은?" |
| 극단 | "예상치 못한 사용으로 어디가 망가질까?" |
| 규모 | "10배 볼륨에서 무엇이 먼저 실패할까?" |

호출당 하나의 관점 — 맹점을 드러낼 가능성이 가장 높은 것.

### 설계

- **논쟁이 아니다** — 관점이 체크아웃되면 확인하고 넘어간다. 반대를 위한 반대가 아님
- **브레인스토밍이 아니다** — 브레인스토밍은 가능성을 탐색하고, flip은 기존 결론을 검토한다
- **당신이 결정한다** — flip은 관점을 제공하고, 결론은 항상 당신의 것
- **설정 가능** — 힌트 레벨: 끄기 / 주요 결정 시 / 모든 결론 시

## 왜 déjà vu 인가

| | 기존 방식 | déjà vu |
|---|---|---|
| 경험 저장 | CLAUDE.md / .cursorrules 수동 작성. 사람은 잊는다 | 명령어 하나, AI가 추출, 당신이 확인 |
| 경험 검색 | grep 수동, 채팅 기록 스크롤, AI에 다시 질문 | `/gotcha <키워드>`, 밀리초 히트 |
| 결정 검토 | 직감, 경험, 코드 리뷰 | `/flip`, 체계적 관점 전환 |
| 토큰 오버헤드 | 규칙 파일 전체 로드. 사용하지 않아도 지불 | 사전 주입 제로. 검색할 때만 지불 |
| 의존성 | 임베딩 API, 벡터 데이터베이스 | grep + 파일시스템, 외부 의존성 제로 |

---

## 설계 철학

- **토큰을 낭비하지 않는다** — 요청 시 검색만. 사전 주입 없음, 백그라운드 매칭 없음
- **외부 의존성 제로** — grep + 파일시스템. 이해 가능, 디버그 가능, 비용 제로
- **몰입을 방해하지 않는다** — 저장 여부는 당신의 선택. 한 번의 부드러운 알림, 강요 없음
- **당신이 주도한다** — 경험과 관점을 제공할 뿐. 결론은 항상 당신의 것
